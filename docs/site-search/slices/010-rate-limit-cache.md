# 010 — Нагрузка

Тип: поведение
Основание: NFR-4, NFR-1
Зависимости: 002 (backend-половина)
Половины: только backend
Результат: поиск выдерживает частые запросы и защищён от злоупотребления

## Контракты
- `contracts/search.openapi.yaml` — ответ 429 (не меняется)

## Приёмка
AC-010-1 Обычный пользователь
  WHEN клиент делает 5 запросов подсказок в секунду
  THEN все ответы 200

AC-010-2 Злоупотребление
  WHEN клиент делает 30 запросов в секунду
  THEN запросы сверх 20 в секунду получают 429

AC-010-3 Наличие не устаревает
  WHEN «Ноутбук X17» был в выдаче, затем продана последняя единица
   AND через 1 с снова запрос «ноутбук»
  THEN «Ноутбук X17» помечен как не в наличии (AC-008-4 не сломан)

AC-010-4 Снятые с продажи
  WHEN товар снят с продажи
  THEN не позже чем через 30 с он не появляется в выдаче (FR-15)

AC-010-5 Нагрузка
  WHEN 50 клиентов печатают одновременно
  THEN p95 ≤ 150 мс, ни одного 429 у клиентов ≤ 5 запросов/с

## Границы
Вне slice: обновление индекса при изменении товара (011).

## История
Найден конфликт на review-slices: кэш против AC-008-4 и FR-15.
Решение в Dev Spec: допустимая задержка для снятых с продажи — 30 с; наличие не кэшируется.

## Definition of Done
- Все AC-010-* закрыты тестами с AC-ID в названиях
- Change удалён
