# 011 — Свежесть индекса

Тип: поведение
Основание: FR-15
Зависимости: 001
Половины: только backend
Результат: изменения товара в админке доходят до поиска, снятые с продажи не показываются

## Контракты
- порт `SearchIndex`
- МЕНЯЕТ КОНТРАКТ: использует событие «товар изменён» из модуля каталога (подписка),
  сам модуль каталога не меняет

## Приёмка
AC-011-1 Новое название
  WHEN в админке «Ноутбук X15» переименован в «Ноутбук X15 Pro»
  THEN запрос «pro» находит его

AC-011-2 Снят с продажи
  WHEN «Ноутбук X15» снят с продажи
  THEN запрос «ноутбук» его не возвращает (с учётом задержки FR-15)

AC-011-3 Возвращён в продажу
  WHEN «Ноутбук X15» снова в продаже
  THEN запрос «ноутбук» его возвращает

AC-011-4 Новый раздел
  WHEN товар перенесён в раздел «Игровые ноутбуки»
  THEN поиск в разделе «Ноутбуки» его находит (FR-12)

## Границы
Не правит код модуля каталога — только подписывается на его событие.
Найдено на review-slices: иначе 011 пересекался бы с чужой зоной ответственности.

## Definition of Done
- Все AC-011-* закрыты тестами с AC-ID в названиях
- Change удалён
