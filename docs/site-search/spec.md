# Site Search — Dev Spec

Статус: одобрено · Источник решений: [brainstorming.md](brainstorming.md)

Документ описывает только поведение. Здесь нет эндпоинтов, таблиц, файлов и библиотек:
форма данных — в контрактах (slice 001), технические решения — в `docs/adr/`.

## Цель
Покупатель находит товар без перехода в каталог: открывает поиск с клавиатуры
и видит подсказки по мере ввода с учётом раздела, в котором находится.

## Функциональные требования

**FR-1 Открытие с клавиатуры.** Ctrl+K (Windows/Linux), Cmd+K (macOS), «/».
Работает при любой раскладке. Пока открыт модальный диалог, хоткеи поиска не работают.
- Пример: русская раскладка, Ctrl+Л → поиск открыт.
- Пример: открыта корзина, Ctrl+K → поиск не открывается.
- Пример: поиск уже открыт, Ctrl+K → фокус в поле, текст выделен.

**FR-2 «/» при наборе текста.** «/» не открывает поиск, если курсор в любом поле ввода
(включая редактор отзыва). Ctrl/Cmd+K работает и там.
- Пример: курсор в поле отзыва, нажали «/» → в поле появился «/».

**FR-3 Подсказки.** Появляются после ввода 2 символов и паузы 200 мс:
до 8 товаров и до 3 категорий. В подсказке товара: название, цена, раздел.

**FR-4 Раздел.** На странице раздела поиск идёт внутри него.
Переключатель «Во всём магазине» расширяет область.
Если в разделе ничего нет — заголовок «В разделе ничего не нашлось»,
ниже результаты по всему магазину, переключатель в положении «везде».
- Пример: «Ноутбуки», запрос «чехол» → только чехлы из раздела.
- Пример: «Ноутбуки», запрос «мышь» → «В разделе ничего не нашлось» + мыши из всего магазина.

**FR-5 Свежая выдача.** На экране всегда выдача по последнему введённому запросу.
- Пример: ввели «нау», затем «ноут»; ответ на «нау» пришёл последним → видна выдача «ноут».

**FR-6 Клавиатура.** ↑/↓ — выбор подсказки, Enter — открыть, Esc — закрыть
и вернуть фокус туда, где он был до открытия.

**FR-7 Enter без выбора** → страница результатов поиска по запросу.

**FR-8 Пометка наличия.** Товар без остатка помечен «Нет в наличии».
Пометка доступна скринридеру как текст.

**FR-9 Раскладка.** Если по запросу пусто, ищем его в другой раскладке (EN→RU).
Если нашли — заголовок «Показаны результаты для „ноут“».
Порядок с FR-4: сначала перевод раскладки в разделе, потом весь магазин.
- Пример: «yjen» → результаты для «ноут».

**FR-10 Нормализация.** Регистр, «ё» = «е», лишние пробелы не влияют на выдачу.
- Пример: «Ёлка  » и «елка» дают одинаковую выдачу.

**FR-11 Словоформы и начало слова.**
- Пример: «ноутбука» и «ноут» находят «Ноутбук X15».

**FR-12 Подразделы.** Поиск в разделе охватывает все его подразделы.
- Пример: «Ноутбуки» включает «Игровые ноутбуки».

**FR-13 Порядок.** В наличии → релевантность → продажи за 30 дней.
Клиент порядок не меняет.

**FR-14 Наличие на момент запроса.** «В наличии» = есть хотя бы на одном складе.
- Пример: купили последнюю единицу → следующий запрос показывает «Нет в наличии».

**FR-15 Снятые с продажи** товары не появляются в выдаче. Допустимая задержка — до 30 с.

## Нефункциональные требования

**NFR-1** Ответ подсказок: p95 ≤ 150 мс на каталоге 50 000 товаров.
**NFR-2** Доступность: панель — combobox по WAI-ARIA, фокус не уходит из панели, пока она открыта.
**NFR-3** Мобильные (< 768 px): открытие только по иконке, хоткеев нет.
**NFR-4** Не более 20 запросов подсказок в секунду на клиента. Обычный пользователь лимит не замечает.
**NFR-5** Поиск недоступен → не позже чем через 1 с сообщение «Поиск временно недоступен»,
остальная страница работает.

## Вне scope
Семантический поиск, исправление опечаток, недавние запросы, учёт региона покупателя,
статусы «под заказ», аналитика запросов, рекламные позиции.
